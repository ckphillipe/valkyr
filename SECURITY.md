# Security policy

## Reporting a vulnerability

Please use GitHub's private vulnerability reporting for this repository. Do
not open a public issue, publish a proof of concept, or disclose credentials
until maintainers have had a reasonable opportunity to investigate and fix the
issue.

Include affected version/commit, reproduction steps, impact, and any suggested
mitigation. Do not include real API keys, private database URLs, or encrypted
customer data.

## Supported versions

Before the first public release, security fixes are made against the current
default branch. The published support policy will be updated with each release.

Repository administrators must enable private vulnerability reporting in GitHub
settings before publishing `v0.1.0`.
